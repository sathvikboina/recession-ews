Leakage firewall

Assume the table is guilty. Make the tests prove it is not.

A clean-looking backtest can hide a target, a future value or a full-sample scaler. The firewall is a small set of tests written against the builder, including mutations that must fail.

What is forbidden

  • The recession flag R and episode identifiers.
  • The BEAI factor, cumulated level or diffusion share.
  • Turning-point dates and the NBER chronology.
  • Country identifiers and raw country-size levels.
  • Any value dated after the prediction origin.
  • Any scaler or imputer fitted on the full sample.

How it is checked

Seven tests run against ews.features. The key one rebuilds the table on history truncated at four different cutoffs: if any past value changes, the table is reading the future. Two mutation checks then poison a clean table and require a failure.

Adversarial by design

    What the suite does

    A suite that only passes on clean data is not a firewall. The mutation test is the point.

    The seven tests

    Each one maps to a rule in the build contract.

    TestWhat it enforcesRuleFailure mode
    Schema147 contiguous quarters, 149 unique columnsC-01silent window drift
    BlacklistNo label, factor, chronology or identifier columnC-01 / FW-06target leakage
    UnscaledNo standardised column; rate levels match sourceC-07 / C-08full-sample scaling
    No future leakageTruncated rebuild leaves past values identicalC-05look-ahead
    IndependenceBEAI copies reproducible from the panel aloneC-01shared fitted object
    MutationPoisoned tables must fail the checksC-01 / C-05toothless tests
    InventorySpec, dictionary and table agree at 149 columnsC-07documentation drift
