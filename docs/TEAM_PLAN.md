# Team Plan: Four Work Packages

Status: **active 2026-11-05.** This is the working plan for four teammates. It
replaces the single “next five actions” list in `docs/STATE.md`.

A plain-English Excel version is `Team_Plan.xlsx` (12 sheets, generated by
`make team-plan`). It contains the same four packages plus the task detail, five-week
parallel schedule, hand-offs, combination rules, risks, final review and glossary. Edit
`scripts/make_team_plan.py` and regenerate; do not hand-edit the workbook.

The project is label-first. The USA label is already built, validated and frozen
as `labels-v2`. No feature table and no model exist yet. The next milestone is
two more country labels (Japan and Germany), then a leakage-safe feature/harness
layer, then the model and ensemble evaluation. India is audited separately because
it probably cannot pass the §19 gate.

## Ground rules for every work package

1. **Do not change the USA label.** `labels-v1` is byte-identical in
   `outputs/labels/archive/labels-v1/`; `labels-v2` is active. Any change to a
   label input needs a new version, a new decision record and a re-validation.
2. **Do not add an ensemble after seeing scores.** The ensemble is pre-registered
   in `docs/PROPOSAL_ADDENDUM.md`. The rule is frozen before results.
3. **No leakage.** Walk-forward only; every scaler, selector, model parameter,
   weight and threshold is fitted inside the training fold; the test block is
   untouched; a held-out country contributes nothing.
4. **One active source row per scope key.** Raw downloads are immutable under
   `data/raw/<source>/<date>/`; provenance goes in `data/manifest.csv`,
   `data/fred_verification.csv` and `data/series_resolution.csv`; retirements go
   in `data/superseded_series.csv`.
5. **Missing stays missing.** No interpolation, no forward fill, no partial-quarter
   imputation. A country that fails the gate is a finding, not an exception.
6. **Record decisions when made.** Use `decisions_log.csv` and
   `docs/DECISIONS.md`; do not rewrite history after seeing results.
7. **One branch per package.** Open a PR with a short description, the commands
   run, the hashes that changed and the tests that pass. Do not merge a red
   `make check test`.
8. **Regenerate, do not hand-edit, generated artefacts.** `config/*.yaml` comes
   from `spec.py`; `data/scope.csv` comes from `scripts/scope_catalog.py`; the
   workbook comes from `scripts/make_worklog.py`.

## Part 1 — Japan and Germany labels now

**Owner:** data/label lead (one person; can pair with a second for source checks).
**Goal:** build two independent BEAI labels, one per country, with the same
frozen estimator and the same validation discipline as the USA. This is the
largest gap in the project: every current result rests on four US recessions.

### Why this is first

The project claims cross-country relevance but has one country. A second and third
label are more valuable than another model on the US sample. The label is the
foundation; without it there is nothing honest to forecast.

### Tasks

1. **Resolve sources before downloading.**
   - Japan: BOJ Time-Series Data Search / e-Stat / Cabinet Office-ESRI, then OECD
     QNA/STES. Record the exact dataflow, key dimensions and series code.
   - Germany: OECD QNA/STES, then BIS/Destatis where the chain requires it.
   - Use the §7 chain order. Do not substitute a convenience source without a
     logged decision.
   - For every core indicator, write one row in `data/series_resolution.csv` with
     `source`, `source_id`, `status`, `native_freq` and a note.
2. **Write the fetcher.**
   - Add `scripts/fetch_oecd.py` (OECD SDMX) and/or `scripts/fetch_boj.py`.
   - Respect the OECD limit of 60 downloads/hour. Cache raw payloads under
     `data/raw/<source>/<retrieval-date>/`.
   - Write SHA-256, title, units, frequency, SA status, first/last observation and
     window coverage to `data/manifest.csv` and `data/fred_verification.csv`
     (or a country-specific verification file with the same columns).
   - Never overwrite an existing raw file; a re-fetch gets a new date directory.
3. **Generalize the harmoniser.**
   - Refactor `scripts/harmonize.py` to accept `--country` and read the country's
     `data/series_resolution.csv` rows. Keep the USA path byte-identical.
   - Implement C-06 (monthly → quarterly mean, complete quarters only), C-02
     (Δlog + sign alignment) and C-03 (no imputation).
   - For Q-02, construct real non-residential business investment only if the
     country publishes the three asset components and a non-residential deflator.
     If not, the component is missing; do not substitute total GFCF.
   - For Q-04, prefer quarterly national-accounts employment; use LFS quarterly
     mean only as the fallback. One concept per country, counted once toward 6/8.
   - For Q-05, use quarterly total hours only. Annual-only data stay missing.
4. **Apply the coverage gate.**
   - Compute each core indicator's coverage over 1990Q1–2025Q4 (144 quarters,
     70% = 101).
   - A country is eligible only with ≥6 of 8 at ≥70%. If it fails, stop and write
     the finding; do not tune the gate.
   - Record the component count and the missing indicators in
     `docs/VERIFICATION.md`.
5. **Build the label.**
   - Generalize `scripts/03_labels.py` to `--country`. The estimator, BBQ
     parameters, diffusion gate and reporting window are frozen; only the inputs
     change.
   - Output `outputs/labels/JPN/` and `outputs/labels/DEU/` (or an agreed
     country-prefixed layout). Do not move or overwrite the USA files.
   - Freeze each country's first label as `labels-v1-JPN` / `labels-v1-DEU` with
     input/output hashes and a metadata JSON.
6. **Validate against the country chronology.**
   - Japan: ESRI reference dates from `label_references.csv` (1991Q1–1993Q4,
     1997Q2–1999Q1, 2000Q4–2002Q1, 2008Q1–2009Q1, 2012Q1–2012Q4, 2018Q4–2020Q2
     as of the July 2022 determination; check for later releases).
   - Germany: the official Sachverständigenrat / OECD recession chronology; record
     the exact source and date in `label_references.csv`.
   - Report matched episodes, false episodes, missed episodes and boundary
     differences. A mismatch is a finding; never tune to the chronology.
7. **Write the country validation note.**
   - `docs/LABEL_VALIDATION_JPN.md`, `docs/LABEL_VALIDATION_DEU.md`.
   - Include the source table, coverage table, label dates, chronology comparison,
     robustness variants and falsification checks.
8. **Update provenance and docs.**
   - `docs/VERIFICATION.md`, `docs/STATE.md`, `docs/DECISIONS.md` (new decision
     records for any source substitution), `README.md`, work log.
   - Do not create a frozen tag until the whole bundle is approved.

### Acceptance criteria

- 21/21 scope rows per country have a resolved source or an explicit
  `PENDING_VERIFICATION` with a reason.
- Every active row has one source, a retrieval date, a SHA-256 and a coverage
  figure.
- The country passes 6/8 at ≥70%, or the failure is documented with the missing
  indicators named.
- The label is reproducible from `make` commands and has a metadata JSON with
  input and output hashes.
- The chronology comparison is written and does not use the chronology as a
  tuning target.
- USA label hashes are unchanged.
- New tests pass; `make check test` is green.

### Deliverables

`data/series_resolution.csv` rows, raw downloads + manifest, `JPN_levels/growth`
and `DEU_levels/growth`, `outputs/labels/JPN/*`, `outputs/labels/DEU/*`,
`docs/LABEL_VALIDATION_JPN.md`, `docs/LABEL_VALIDATION_DEU.md`, updated
`docs/VERIFICATION.md` and `docs/STATE.md`.

### Risks / fallbacks

- OECD dataflow IDs are the main unknown. Resolve the dataflow structure first;
  do not guess series keys.
- If a country lacks Q-02 or Q-05, treat the component as missing (Q-02/Q-05).
- If a country fails 6/8, it gets no BEAI label; report it like India.
- If the BOJ API is awkward, use the OECD mirror only with a logged source note.

## Part 2 — Feature table and leakage-safe walk-forward harness

**Owner:** ML engineering lead (one person).
**Goal:** turn the verified panel into a predictor-only feature table and a
walk-forward harness that cannot leak the label.

### Tasks

1. **Feature builder** (`src/ews/features.py`, `scripts/05_features.py`).
   - Read `data/series_resolution.csv` and the clean panel. Include only predictor
     rows and the separate predictor copies of BEAI rows (C-01).
   - Implement C-06 aggregation, C-07 transforms, C-05 availability lags.
   - One row per country × quarter; columns named by series, transform and lag.
   - Store unscaled features only. Scaling belongs inside the fold.
   - Never include the BEAI factor, `R`, turning-point flags, diffusion or NBER.
2. **Feature tests** (`tests/test_features.py`).
   - No `beai_eligible = Y` row leaks into the label-side factor.
   - No future observation appears at a prediction origin.
   - No NBER column.
   - No raw country-size level or country id as a feature.
   - Missing stays missing after transformation.
3. **Fold builder** (`src/ews/harness.py`, `scripts/06_folds.py`).
   - Expanding-window walk-forward; initial training block and step size in
     `config/`.
   - Inner folds time-ordered; no random split, no shuffle.
   - `y(t,H)=1` iff onset occurs in `t+1…t+H`; horizons 1Q/2Q/4Q, 2Q primary.
   - Emit `outputs/folds/folds.json` with train/test boundaries, country, horizon
     and seed.
4. **Harness tests** (`tests/test_harness.py`).
   - Fold boundaries move forward only.
   - No test row appears in a training fold.
   - Threshold is locked before the test block.
   - A deliberately shuffled pipeline fails the leakage test.
5. **Baselines.**
   - Majority, term-spread probit/logit, plain logistic.
   - These are the floor, not the headline.

### Acceptance criteria

- `make features` writes `data/clean/dataset.parquet`; `make folds` writes
  `outputs/folds/folds.json`.
- One country × one horizon can be reproduced from a seed.
- Leakage tests pass and a deliberately leaking variant fails.
- No BEAI column is present in the feature matrix.
- The USA label remains byte-identical.

### Deliverables

`src/ews/features.py`, `src/ews/harness.py`, `scripts/05_features.py`,
`scripts/06_folds.py`, `tests/test_features.py`, `tests/test_harness.py`,
`data/clean/dataset.parquet`, `outputs/folds/folds.json`.

## Part 3 — Models, pre-registered ensemble and experiments

**Owner:** modelling lead (one person; can pair with Part 2).
**Goal:** run the six single models and the pre-registered ensemble under the
frozen walk-forward protocol, then report the result honestly.

### Tasks

1. **Implement the single models** (C-09): logistic, elastic net logistic,
   random forest, XGBoost, SVM, MLP. Same time-ordered tuning budget and class
   weights for all. MLP averages ≥3 seeds with early stopping.
2. **Implement REWI.** `Σ β̂ᵢ zᵢ,ₜ`, intercept excluded, z from the training fold
   only. Report the selected features and their stability.
3. **Implement the pre-registered ensemble** exactly as
   `docs/PROPOSAL_ADDENDUM.md`:
   - equal-weight top-3 by inner-fold pooled PR-AUC;
   - same folds, same features, same threshold-locking rule;
   - confirmatory test: ≥0.01 pooled PR-AUC gain, bootstrap CI excludes zero, no
     episode-recall loss;
   - if it fails, report the single model as primary and the ensemble as a
     negative result.
4. **Run the headline experiment.**
   - Per country, per horizon, six singles + ensemble + baselines.
   - Pooled out-of-sample PR-AUC primary; ROC-AUC, recall, precision, F1, Brier,
     confusion matrix secondary.
   - Episode detection, lead time and false-warning episodes.
5. **Run the ablations.**
   - Track 1: A activity, B labour, C income, D credit/financial, E prices/surveys,
     F external/global.
   - Track 2: I = A+B+C, II = +D, III = +E+F.
   - REWI sign agreement and stability.
6. **Run robustness.**
   - COVID with/without 2020; pre-1990 history only if O-1 is approved; diffusion
     and min-phase variants where relevant.
   - LOCO only if ≥6 eligible countries, ≥20 episodes, and no country >40% of
     episodes; otherwise label it exploratory.
7. **Write the results note.**
   - `outputs/results/headline.md`, `outputs/results/episodes.md`,
     `outputs/results/ablations.md`.
   - Include the ensemble decision and the negative result if applicable.

### Acceptance criteria

- `make run` reproduces the headline table from a clean clone with a seed.
- Every result row has a data version, feature list, fold boundaries, model
  parameters, threshold and seed.
- The ensemble rule is applied exactly as pre-registered; no post-hoc change.
- The report states the revised-data caveat and the episode count.
- No forecasting claim beyond what the out-of-sample results support.

### Deliverables

Model implementations, `scripts/07_run.py`, `outputs/runs/*`,
`outputs/results/*`, `docs/EXPERIMENTS.md`.

## Part 4 — India coverage, scope, integration and pitch

**Owner:** data/validation/writing lead (one person; works alongside Parts 1–3).
**Goal:** close the India question, keep the scope honest, and turn the work into
a coherent combined project.

### Tasks

1. **Finish the India audit.**
   - Start from `docs/INDIA_COVERAGE_AUDIT.md`.
   - Download the candidate MoSPI/RBI series; fill `data/india_core_coverage.csv`
     with actual first/last dates, frequency, coverage and status.
   - Confirm the business/non-residential GFCF split and the official retail
     series. Do not substitute total GFCF or an unofficial proxy.
   - Recompute the 6/8 count. Record the result in `decisions_log.csv`,
     `unresolved_questions.csv` and `docs/VERIFICATION.md`.
   - If the result is <6/8 (expected), keep India as a Label-B-only case study
     under O-2; do not relax §19.
2. **Scope decision (O-4).**
   - Do not widen to P0–P2 until JPN and DEU labels pass their own chronology
     checks.
   - If they pass, update `config/scope.yaml`, regenerate `data/scope.csv` and
     `data/scope_coverage.csv`, and record the collection plan.
3. **Integration.**
   - Keep `README.md`, `docs/STATE.md`, `docs/DECISIONS.md`,
     `docs/VERIFICATION.md`, `docs/BUILD_CONTRACT.md` and the work log in sync.
   - Run `make config`, `make scope`, `make check`, `make test` and a clean-clone
     test before each merge.
   - Never hand-edit generated files; regenerate them.
4. **Pitch and wording.**
   - Use “we built and validated a recession label”, not “we predict
     recessions”.
   - The current story: label-first design, leakage discipline, frozen artefacts,
     honest caveats, USA validated, JPN/DEU next, India a coverage finding.
   - Do not claim methodological novelty. Do not claim forecasting performance
     before Part 3 produces out-of-sample results.
5. **Final packaging (after approval only).**
   - Rebuild the bundle/mirror/zip and freeze a tag only when the full bundle is
     approved.
   - A clean clone must reproduce the label hashes, run the tests and build the
     workbook.

### Acceptance criteria

- India coverage is closed with a downloaded-data count, not a guess.
- The scope decision is recorded; no silent widening.
- All docs agree on the current state, test count and label version.
- The pitch contains no unsupported forecasting claim.
- A clean clone passes `make check test`; the final bundle is reproducible.

### Deliverables

`data/india_core_coverage.csv`, updated India decision records,
`docs/INDIA_COVERAGE_AUDIT.md` (final), scope update (if approved), updated
README/STATE/DECISIONS/VERIFICATION/workbook, final bundle/tag after approval.

## Integration contract

| Change type | Required checks | Reviewer |
|---|---|---|
| New country data | one active row per key; manifest hash; coverage table; no imputation | Part 1 + Part 4 |
| New feature | leakage test; no BEAI column; no future data | Part 2 + Part 3 |
| New model | same folds; threshold locked; seed recorded | Part 3 + Part 4 |
| Ensemble change | new dated addendum; never after results | Part 3 + project lead |
| Label change | new version; archive old; re-validate chronology; new decision | project lead |
| Docs/pitch | no forecast claim before results; caveats present | Part 4 |

### Branch and PR rules

- `feat/jpn-label`, `feat/deu-label`, `feat/features-harness`,
  `feat/models-ensemble`, `feat/india-scope-docs`.
- Rebase on `main` before opening a PR.
- PR description: what changed, commands run, tests, hashes, known gaps.
- Do not merge with a red `make check test`.
- Do not commit raw data; commit metadata and hashes only.

## Definition of done for the combined project

- USA, JPN and DEU each have a frozen BEAI label with a chronology comparison.
- India has a downloaded-data coverage verdict and is reported as a case study if
  it fails 6/8.
- The predictor feature table has no BEAI inputs and passes the leakage tests.
- The walk-forward harness reproduces a country × horizon × model result from a
  seed.
- The pre-registered ensemble is evaluated exactly once under its rule; a negative
  result is acceptable and reported.
- `make check test` is green; a clean clone reproduces the label hashes.
- The write-up uses label-validation wording, states the revised-data caveat, and
  makes no forecasting claim that the out-of-sample results do not support.
